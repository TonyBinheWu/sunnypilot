# EV6 HDA2 原始雷達與短暫處理逾時

本次配置為一般未改線的 HDA2 線束、`CanfdHDA2=1`、
`HyundaiCameraSCC=0`，並啟用 openpilot 縱向控制。

## 原始雷達錯誤

接管縱向時，既有啟動程序會停用 ADAS ECU 的原廠 SCC 發送。
故障紀錄顯示，原廠 `0x1A0 SCC_CONTROL` 停止後，原始前方雷達
仍有資料，但 SCC 解析器繼續將缺少原廠訊息回報為 CAN 錯誤。
車輛主 CAN 的 `carState.canValid` 同時仍有效。

修正僅在原始雷達已開啟、CAN FD HDA2、openpilot 縱向接管且非
Camera-SCC 的配置，取消對已停用原廠 SCC 的要求。原始雷達必收
訊息及校驗仍須通過。Camera-SCC、原廠縱向及 passive Bosch 的
原廠 SCC 處理維持原狀；不會把自身傳送的 SCC 當成量測目標。

離線以相同紀錄重播 5,982 批精確配對的 CAN／車況輸入，得到
1,198 次雷達輸出。修正前雷達 CAN 錯誤 428 次，修正後 0 次；
3,644 筆原始前方目標資料一致，輸出節奏也一致。缺少必收原始
雷達訊息的回歸測試仍會報錯。此結果不等於實車控制驗證。

## 視覺與雷達融合

既有 `EnableRadarTracks=1` 會將前方原始雷達與視覺前車匹配，
使用符合條件目標的雷達距離與相對速度；沒有合適匹配時，依既有
可信度與路徑條件使用視覺結果。這不是簡單取兩者平均。
此次沒有改動目標選擇、跟車控制、煞車或轉向演算法。

原廠 SCC 發送已停用時，模式 `2`／`3` 沒有可用的 SCC 備援來源。
角雷達是獨立功能，不會隨本次修正自動啟用。變更雷達來源或
接線設定後需完整重新啟動，讓解析器與車輛配置重新建立。

## 短暫處理逾時

最新行程的摘要紀錄共 57 段。第 53 段的完整紀錄中，有約
88 ms 的雷達錯誤；車況發布間隔最大 107.003 ms，而附近原始
CAN 發布仍持續。當時橫向與縱向控制均未啟用。

同一秒的 `card` 診斷顯示巡航處理段 `state_tail` 最大
96.656 ms，整體工作最大 101.528 ms，單次執行緒 CPU 最大
10.696 ms；該秒排程等待合計約 0.380 ms。這將問題縮小到巡航
處理段的阻塞，不能據此指出確切系統呼叫或斷言雷達運算過慢。

修正將 26 項週期性巡航偏好讀取移到既有背景設定執行緒，以完整
快照交給 CAN 執行緒，保留單位轉換、道路速限計算與設定值。
設定仍可即時套用，正常背景更新與套用合計約為數百毫秒內。
背景讀取失敗保留上一份完整偏好，診斷記錄其年齡；不會產生半份
偏好。此快照不包含 CAN、感測器或雷達物件資料。

只有 GM 控制器會產生 `ActivateCruiseAfterBrake`，因此其他品牌
不再於每個巡航週期讀取此旗標。GM 的讀取、消耗與恢復流程保留。
這也避免其他品牌消耗不屬於自身的舊 GM 指令。

測試以背景讀取被刻意阻塞的情況確認，主執行緒仍可套用完整
偏好；另比對公英制、道路速限變更及 GM 指令處理。
保留雷達輸入 100 ms 時效限制、失效發布及中斷後重建流程。

新增 `cruise_params_ms`、`cruise_buttons_ms`、`cruise_finish_ms`、
背景讀取耗時及快照年齡。`card` 每秒保留最慢 `state_tail` 那一幀
的相關耗時，供區分設定、按鍵／指令與結果回寫。
原紀錄未記下確切讀檔呼叫，因此本次是消除已確認存在的同步
讀檔路徑；是否完全排除實機停頓，仍須更新後的紀錄確認。
